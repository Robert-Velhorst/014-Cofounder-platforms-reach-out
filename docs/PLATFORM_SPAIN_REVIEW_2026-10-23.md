# Spain: CoFounder Match discovery review — October 23, 2026

## Decision

Add `cofounder-match-spain` as a dedicated **discovery-only** listing. It is a
separate domain/brand, not an alias for CoFound at cofound.biz, cofound.lat,
cofound.space or WeFoundy. The catalogue source becomes 70 records: 23 dedicated,
24 community/channel and 23 programme routes; 47 discovery-only and the unchanged
23 manual-reviewed records. These counts do not establish worldwide completeness.

## First-party evidence

The [homepage](https://cofounder-match.com/) describes Spain-focused founder
discovery in Spanish. Advertised compatibility and discreet-profile features
are untested, not identity verification or successful-match evidence. Sample
cards and scores were not treated as real members or outcomes. Navigation offers
registration and routes signed-out exploration to login; member access was not
tested. Eligibility outside Spain is unresolved.

The expanded free-use FAQ on [how it works](https://cofounder-match.com/how-it-works)
advertises profiles, browsing and messaging without payment. This supports an
advertised `free-core` classification, not verified entitlements, future prices,
usage limits or a promise that every service stays free. No payment or signup
was attempted.

The [terms](https://cofounder-match.com/terms) require adults, prohibit collection
of other users' information without consent and forbid unsolicited spam. Their
user-content permission concerns display/distribution within that service, not
reuse by this application. They disclaim outcome guarantees. These observations
do not authorize import, API use or external contact.

The [privacy notice](https://cofounder-match.com/privacy) describes professional,
account, message and technical data, member visibility, providers and possible
transfers outside the EEA. It names the service brand as controller; legal
operator identity was not independently established. Its discreet-mode, security,
retention and deletion declarations were not technically or legally audited.
Visibility or mutual interest is not external collection/contact consent.

The blank [registration form](https://cofounder-match.com/register) requests an
email, password and name, with terms/privacy acknowledgement and a separate
marketing choice. No field or checkbox was changed, and nothing was submitted.
Account admission, verification inbox, member workflows and data rights remain
unverified.

## Method, counterevidence and limits

Search queries covered the exact brand with Spanish privacy, eligibility and
access terms. Indexed policy excerpts carried September dates, whereas both
rendered policy pages displayed October 23. This is an observed discrepancy,
not proof that either policy substantively changed that day; the catalogue date
records this direct review only.

The page reader returned an empty application shell. An isolated signed-out
Chrome context rendered the five linked public pages. Only the free-use FAQ
was expanded. No profile directory, individual profile, account, support link,
creator social page, form submission or message was used. All five task-created
tabs were closed. Search snippets alone were not publication evidence.

StartHawk was also considered during discovery, but it is already a FounderCloud
alias in the repository and was not added again. The held Spanish-language leads
in [the earlier supplement](PLATFORM_SPANISH_LATAM_REVIEW_2026-10-23.md) remain
held; a similarly named service or usable public form does not resolve their
access/operator gaps.

Market-research guidance required first-party reads and counterevidence. It
influenced the decision to list only the discovery route while retaining explicit
permission, privacy, pricing and account-access limits.

## Qualification boundary

On local Windows Node 26.12.0, all 12 new source/policy cases passed using the
actual catalogue, filter and source-policy modules with pinned cached dependencies,
not mocked responses. They first failed against the previous 69-source catalogue.
An in-memory negative control admitted only the new source and caused seven
cases to fail (five search cases still passed); checked-in source then passed
all 12 again. No production file or policy was changed by that negative control.
The scoped strict TypeScript 6.0.3 check returned zero diagnostics.

All 219 native operator/source checks passed, zero failures/skips (9,628.1081 ms).
The first run correctly rejected a stale UI inventory input hash. Review found
only the changed catalogue input and aggregate digest, not changed UI actions;
those two hashes were updated. The 151 input-file and 230 action counts are
unchanged. This is source-integrity evidence, not UI behavior acceptance.

The new source must retain fail-closed candidate-intake, CSV and outreach
admission. The existing browser gate now requires its Spanish alias/domain to
find the exact card, and the existing SSR and regional-admission suites include
the new record. Local source/policy tests are not rendered, database or provider
acceptance. Full exact-head CI, compiled desktop/mobile search/evidence review
and all remaining release gates are required before merging this increment.
No original phase is promoted by this listing or by structural test success.
